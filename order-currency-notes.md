# Order prices: NBKR cross-rate

At the user's request, starting prices and additional-function prices on the order page show a USD estimate alongside their RUB amount. The same estimate is used for development totals and individual selected extras on the review screen. The source is the [National Bank of the Kyrgyz Republic daily XML](https://www.nbkr.kg/XML/daily.xml), not an exchange office's executable quote. NBKR publishes both USD and RUB relative to Kyrgyz som; the calculation is `RUB amount × (RUB KGS value / RUB nominal) / (USD KGS value / USD nominal)`, rounded to whole dollars and marked approximately. The effective date is used for validation but, following the user's correction, is not displayed.

`GET /api/exchange-rates/nbkr` retrieves the official feed server-side, since it has no browser CORS permission. Responses are validated, bounded, cached for one hour and coalesced. A rate announced for a future date is not presented as currently effective. If a refresh fails, a previously fetched rate can be used for at most 24 hours with a visible cached indication; otherwise the interface displays an unavailable indicator rather than inventing a rate. The UI refreshes periodically. This is a display estimate; the existing pricing model and Telegram draft remain in RUB.

Verification includes parsing and nominal-unit tests, invalid and oversized responses, cache/expiry behavior, a public GET access check, and mobile UI checks with current, cached and unavailable rate responses. Live upstream reachability from Railway must be confirmed after a future deployment; local access alone cannot establish it.
